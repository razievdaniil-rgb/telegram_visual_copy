# Сборка iPhone 16 — текущая передаваемая

[Скачать артефакт](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/41108481160) → Artifacts → `Telegram-iPhone-IPA-needs-signing`. Требуется вход в GitHub; хранится до 6 ноября 2026. Внутри ZIP: `Telegram.ipa`, `verification.json`, `app-source-sha.txt`.

- Telegram iOS 13.1.1, build 16, коммит `c19637d`, `release_arm64` без установочной подписи.
- Артефакт 71,9 МБ. Длительность сборки 102 минуты.
- Шаг `verify_ipa.py` прошёл в CI: ZIP, одно приложение, `arm64`, платформа `IOS`, оба framework непустые.

## Что отличает её от build 13, который ставили на телефон

Журнал этапов с физического iPhone (build 13) оборвался так: `22 ms window`, `157 ms container`, `211 ms window-visible` — без `storage`. `window-visible` выполняется в обработчике сцены, уже после возврата из `didFinishLaunchingWithOptions`, а список этапов хранится в памяти и не может потерять записи. Значит метод вышел досрочно между `container` и `storage`. В этом промежутке два досрочных выхода, и выход по отсутствию контейнера в локальном режиме невозможен — остаётся проверка записи во временный файл.

В build 16:

1. **Проверка записи не обрывает локальный запуск.** Алерт этой ветки выводится на ещё невидимое окно, поэтому на телефоне она неотличима от пустого экрана и не сообщает ничего. Для реальной клиентской сборки проверка остаётся жёсткой остановкой.
2. **Она различает причину отказа** и пишет её в журнал: `open-failed errno N at <path>` либо `short-write N errno M`.
3. Каталог `telegram-data` создаётся синхронно, до того как в него пишут ключ устройства и выполняют проверку записи.
4. Отключена upstream-очистка контейнера: она удаляет все каталоги кроме `telegram-data` и `Library`, что в контейнере App Group безопасно, а в домашнем каталоге приложения означает удаление `Documents` и `tmp`.

## Чего не установлено

**Почему проверка записи не прошла на телефоне.** Первоначальное объяснение — отсутствие каталога — опровергнуто: `TempBox.tempFile` создаёт каталог с `withIntermediateDirectories: true`, а `ManagedFile(.readwrite)` открывает файл с `O_RDWR | O_CREAT`. QA #32 подтверждает это независимо: чистый первый запуск прошёл в симуляторе **на исходниках до исправления**.

Поэтому build 16 гарантирует не работоспособность, а отсутствие немого отказа: либо интерфейс открывается, либо экран называет место и причину. Исправления 3 и 4 верны сами по себе, но объяснением той проверки не являются.

Следующий шаг определён заранее по коду `errno`: права доступа (`EPERM`/`EACCES`) — переносить хранилище в `Library/Application Support`, штатное место для данных приложения, которое подмена контейнера обошла; `ENOSPC` — нехватка места на устройстве, к сборке отношения не имеет.

## Что проверено в симуляторе

QA #32 — первый за всё время проекта прогон чистого первого запуска (`fresh`, без `seed_demo`) и первый на оптимизированной конфигурации: успешно. То есть оптимизация функционал не сломала. Запуск на физическом iPhone этим не подтверждается: в симуляторе нет launch watchdog, не проверяются entitlements, нет постраничной проверки подписи и процессор несопоставимо быстрее.

# Архив: оптимизированная сборка iPhone 14

[Скачать артефакт](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/41067405588) → раздел Artifacts → `Telegram-iPhone-IPA-needs-signing`. Требуется вход в GitHub; артефакт хранится до 6 ноября 2026. Внутри ZIP: `Telegram.ipa`, `verification.json`, `app-source-sha.txt`.

- Telegram iOS 13.1.1, build 14, коммит `a2472ba`.
- Конфигурация **`release_arm64`** без установочной подписи — прежние поставки собирались как `debug_arm64`.
- Артефакт **71,9 МБ** против 609 МБ у build 12: в 8,5 раза меньше.
- Длительность сборки 83 минуты.

Отличия от build 12 только в способе сборки и в диагностике запуска. Ни один экран, компонент, отступ, шрифт, цвет или ресурс не менялся; согласованный функционал сохранён целиком.

## Проверено

Шаг `verify_ipa.py` прошёл в CI: целостность ZIP, ровно одно приложение в пакете, `arm64`, платформа `IOS` (не симулятор), оба основных framework непустые. Сборка не дошла бы до успеха, если бы он упал.

## Не проверено

- **Запуск на физическом iPhone.** Ни устройства, ни Mac, ни логов с телефона в этой среде нет. Проверка передана исполнителю с живым iPhone.
- Пакет не осмотрен локально: артефакты GitHub отдаются только по авторизации.
- Прогон в Simulator на этой же конфигурации — сборка #23 упала по лимиту времени на шаге (60 минут при 83 минутах у device), лимиты поднены, идёт #24.
- Причина белого экрана не установлена. Исправлена конфигурация сборки, которая была неприемлема сама по себе; причиной она не объявляется.

## Диагностика в этой сборке

Если интерфейс не появился за 8 секунд, вместо пустого белого экрана показывается список этапов запуска с миллисекундами, и он убирается сам, как только интерфейс встал. Полный журнал — `Файлы → На iPhone → Telegram → TelegramSimulator/launch-trace.txt`, журнал предыдущего запуска лежит рядом. Если список этапов не появился вовсе, это тоже ответ: ему нужен главный поток, значит он заблокирован, и читать нужно файл.

Диагностика нужна только до подтверждения запуска. После него собирается чистая клиентская сборка без экрана этапов и без `UIFileSharingEnabled` — ноль отступлений от оригинала.

- Размер IPA 609032044 байта.
- SHA256 `4303cd192001efdef8eaabab7f8e3c8dd2dc6ecbbd7fdb571e5780d4bee07789`.

Один IPA содержит шестерёнку в нижних настройках, экран настроек с собственным фото, меню без отдельной нижней лупы, полный оригинальный узор и локальную смену общих обоев. Предыдущие build 7–9 исторические; для передачи используйте build 12.

На iPhone 13 Pro Max Simulator / iOS 27.0 в QA #30 прошли меню, смена общего фона, отправка/правка, сохранение после изменения профиля и перезапуска, сброс. В [QA #31](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/40795917058) прошли оба аватара и полный редактор (85 + 172 команды), включая сохранение после перезапуска. Просмотрены 34 контрольных снимка этого прохода. [Отчёт](builds/native-client-qa31-summary.json). [Новое видео 2:59,7](FEATURE_VIDEO.md) показывает эту сборку, включая обои, оба аватара и редактор. Старое видео build 7 сохранено как история.

## Установка и использование

IPA требует подписи при установке. [Инструкция для Windows](../native/INSTALL_WINDOWS.md). В Downloads рядом с Telegram-client.ipa находится Инструкция-Telegram-iPhone.txt с краткими действиями для проверяющего. Физическая установка через Sideloadly и запуск ещё не подтверждены.

Редактор открывается удержанием центрального заголовка «Чаты» 1–2 секунды. Общие обои меняются через Настройки → Оформление → Обои для чатов. JSON-резервная копия содержит профили/чаты/сообщения, но не настройки обоев и фоновые фотографии. Не удаляйте приложение без резервной копии.

Выбор фотографии как обоев и личные обои отдельно через UI ещё не проверены. Реальная клавиатура, системные разрешения, производительность и подпись требуют проверки на iPhone. Совпадение всех экранов с App Store Telegram попиксельно не заявлено.
