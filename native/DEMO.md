# Демонстрация нативной версии

Workflow `Native Telegram - simulator video` собирает исходный Telegram iOS с локальными дополнениями. Архивный Expo-прототип здесь не используется.

Создаётся отдельный новый iPhone Simulator. До первого запуска в его собственный контейнер записываются вымышленные профили и переписки через обычный документ версии 1. Производственная сборка не содержит автоматического заполнения демонстрационными данными.

Ожидания до записи: список показывает два личных чата; диалог — входящие/исходящие сообщения, длинный текст, явный перенос и emoji. При открытии диалога/профиля исходная навигация перемещает экран целиком, без белых промежутков и повторяющихся пузырей. Время и галочки остаются внутри пузырей; клавиатуру и системные области рисует iOS. Удержание центральной области заголовка открывает отдельный UIKit-редактор, его кнопки отсутствуют на публичном экране.

Видео записывается `simctl io recordVideo` с исходными временными метками. `scripts/inspect-recording.py` получает PTS через ffprobe и извлекает кадры по индексам; контактный лист подписывает реальный номер кадра и время. Успех компиляции сам по себе не подтверждает внешний вид или запуск.

Артефакт `Native-Telegram-simulator-app` загружается сразу после компиляции. Для повторной записи без пересборки задайте `app_run_id` при ручном запуске workflow либо `simulator_app_run_id` в `native/demo-request.json`. SHA исходников приложения сохраняется рядом с видео; изменение сценария не меняет готовый бинарник.

Артефакт `Native-Telegram-video-and-screens` содержит MP4, снимки, отчёт проверки архитектуры и диагностику. При ошибке он может содержать только диагностику — наличие артефакта ещё не означает, что ролик готов.

Управление в изолированном CI выполняет Maestro из официального релиза; XcodeBuildMCP в этой сессии недоступен. Доступ к удалённому рабочему столу Actions не предоставляется. Интерактивный сервис потребует отдельного размещения simulator `.app`, а не готового device IPA.

## Регрессия по ТЗ

`qa-suite.yaml` объединяет публичные экраны, редактор профилей/чатов, добавление за обе стороны, изменение текста/галочек, перезапуск и ручные статусы. Один процесс Maestro сохраняет один XCTest-сеанс: в проверке «до» повторный запуск CLI завис ещё до выполнения команд. Сценарий ограничивается по времени через `record_scenario.py`; при тайм-ауте останавливается только его группа процессов и финализируется MP4. Предыдущая запись не теряется из-за зависшего теста.

Проверяемые пункты и ограничения перечислены в [матрице приёмки](../docs/NATIVE_REQUIREMENTS_QA.md). Пример содержит исключительно вымышленные профили и сообщения; исходный документ приложения в диагностические артефакты не выгружается.
