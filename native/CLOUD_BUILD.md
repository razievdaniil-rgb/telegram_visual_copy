# Сборка iPhone IPA без собственного Mac

Для этого проекта используется **GitHub Actions → Native Telegram - unsigned iPhone IPA**:

[Открыть сборку](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/workflows/native-build.yml)

Это полноценная компиляция оригинального Telegram и наших дополнений на облачном Mac. Предыдущий workflow **Native Swift sources** проверяет только исходники и модель — его ZIP не является приложением.

**Историческая device-сборка (не текущая поставка):** [bf3488d — успешно](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/40363919274). [Скачать ZIP с Telegram.ipa и отчётом](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/40363919274/artifacts/12673175127). Это отладочная сборка для iPhone, которая требует последующей подписи. Установка на устройство ещё не подтверждена.

## Что делает workflow

1. Запускает стандартный arm64 runner `xcode-27`, выбирает Xcode 27.1 и записывает фактические версии macOS/Xcode/SDK в отчёт.
2. Получает зафиксированный Telegram iOS 13.1.1, рекурсивные зависимости и наш патч.
3. Компилирует `debug_arm64` для настоящего iPhone. Расширения отключены. Apple ID и сертификаты разработчика не используются.
4. Формирует IPA без подписи для установки. Режим явно называется `build-unsigned-device`; обычная подписанная сборка по-прежнему требует отдельной конфигурации и профилей.
5. Проверяет целостность ZIP, структуру приложения, наличие TelegramCore/TelegramUI frameworks, архитектуру arm64 и Mach-O platform IOS. Сборка симулятора проверку не пройдёт.
6. При успехе публикует артефакт **Telegram-iPhone-IPA-needs-signing**, внутри `Telegram.ipa` и `verification.json`. При любой ошибке сохраняет диагностические логи.

Совпадение версии Xcode проверяется скриптом; требования исходников не обходятся. В выбранных [официальных образах GitHub](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md) доступен Xcode 27.1. Очередь, время загрузки зависимостей и длительность компиляции зависят от GitHub. Используется стандартный runner, не `xlarge`.

## Как повторить с Windows

1. Открыть ссылку выше и войти в свой GitHub.
2. Нажать **Run workflow → main → Run workflow**.
3. Открыть появившийся запуск. Дождаться завершения задания `compile`.
4. При зелёном результате скачать **Telegram-iPhone-IPA-needs-signing** из раздела Artifacts внизу страницы запуска. Распаковать ZIP.
5. Если сборка красная, открыть неуспешный шаг или скачать **Native-Telegram-build-diagnostics**. Не считать появление workflow доказательством успешной компиляции.

Для повторной попытки после исправления исходников используется кнопка Run workflow. Ведущий разработку агент также может увеличить `attempt` в `native/cloud-build-request.json`: его push запускает сборку именно текущей версии кода.

## Установка — отдельный шаг

Полученный файл предназначен для последующей подписи, например через [Sideloadly](https://sideloadly.io/) на компьютере клиента. Он **не устанавливается напрямую как APK**. Вход в Apple ID выполняется на компьютере владельца; пароль в GitHub Secrets для этой сборки не нужен.

Работу App Groups, Keychain и переподписи нужно проверить на конкретном iPhone/iOS. Успешная компиляция и проверка arm64 не доказывают, что приложение уже установлено, запускается и сохраняет данные после обновления подписи. Подпись и проверка установки не выполняются workflow автоматически.

## Свободное место перед сохранением кэша

В запуске `40643112865` компиляция прошла, но `actions/cache/save` вывел `No space left on device`; статус шага при этом остался успешным. Поэтому одного зелёного шага недостаточно для подтверждения сохранённого кэша. Перед следующими архивированиями workflow вызывает `reclaim_ci_build_space.py` после загрузки IPA: он доступен только в macOS GitHub Actions, проверяет абсолютные пути одноразового upstream-checkout и отдельного IPA, очищает вывод Bazel и удаляет этот одноразовый клон. Репозиторий проекта, пакет IPA, журналы и `~/telegram-bazel-cache` сохраняются; SHA-256 IPA проверяется до и после очистки. Скрипт отказался запускаться в локальной Windows-проверке. На следующих итерациях #9 и #10 кэш действительно сохранился; в #11 снова встретилась нехватка места. Очистка не гарантирует сохранение каждого кэша. Наличие IPA и прохождение его проверки учитываются отдельно от успешности архивирования кэша.

## Свободное место до компиляции — 28 октября

В iPhone run 40678806736 компиляция дошла до обработки TelegramUIFramework, но запись выходного архива и кэша завершилась `No space left on device`. До восстановления кэша на runner было около 35 GiB. После этого одного освобождения Bazel перед сохранением кэша недостаточно.

`preflight_ci_disk.py` требует минимум 50 GiB ещё до восстановления кэша. Только в macOS GitHub Actions и только при нехватке места он удаляет предустановленный Android SDK по проверенному пути `~/Library/Android/sdk`. Он сохраняет Xcode 27.1, все iOS SDK и симуляторы, исходники и Bazel-кэш. На локальной Windows-машине скрипт отказывается запускаться. Если места всё равно мало, задание останавливается сразу до длительной компиляции. Само освобождение и последующий успешный IPA должны подтверждаться новым журналом.
