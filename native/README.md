# Нативный симулятор на исходниках Telegram iOS

Активное направление с 26 октября 2026. Основа — **Telegram iOS 13.1.1**, ревизия `fb0e62ba8a147f0821da6aa63c09da7d79a10111`. Это доработка оригинального Swift/UIKit/AsyncDisplayKit-приложения. Expo и web не используются внутри нового приложения.

**Статус: iPhone IPA скомпилирован в облаке.** [Полная сборка bf3488d успешна](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/40363919274); подтверждены arm64, платформа IOS, целостность ZIP и наличие оригинальных frameworks. [Скачать артефакт](https://github.com/razievdaniil-rgb/telegram_visual_copy/actions/runs/40363919274/artifacts/12673175127). Это тестовая `debug_arm64` сборка без установочной подписи. Запуск, внешний вид и установка на iPhone ещё не проверены; перед установкой нужна подпись. Собственный Mac не требуется для повторения облачной компиляции.

## Состав

- `Sources/Core/SimulatorDocument.swift`: документ версии 1, профили, личные чаты, текстовые сообщения, ручные даты/стороны/галочки/статусы, проверка данных, атомарное JSON-хранение.
- `Sources/Core/TelegramSimulator.swift`: локальный аккаунт без SMS-входа и проекция данных в оригинальный Postbox; перехват отправки, изменения и удаления; локальные ресурсы аватаров и поле «О себе».
- `Sources/UI/SimulatorEditorController.swift`: отдельный служебный редактор на UIKit, выбор аватара, импорт/экспорт JSON. Публичные экраны не переписаны.
- `patches/0001-local-simulator.patch`: небольшие изменения оригинальных точек запуска, сети, действий с сообщениями и отображения ручных галочек.
- `scripts/prepare.py`: получение строго зафиксированной версии, применение патча и копирование Swift-файлов в модули, которые upstream собирает через `Sources/**/*.swift`.
- `scripts/build.py`: генерация Xcode-проекта, сборка для симулятора или устройства через оригинальный `Make.py`. Не устанавливает приложение и не публикует его.
- `Package.swift`, `Tests/`: отдельные переносимые тесты модели. Сам Telegram **не** собирается через SwiftPM.

Большой оригинальный репозиторий не дублируется в истории этого проекта. Здесь хранятся pin, точный патч и все новые исходники. Подготовленный checkout получается воспроизводимо; исходная история Telegram сохраняется в нём.

[Карта оригинальных компонентов и точек подключения](COMPONENT_MAP.md).

**Нет своего Mac:** [облачная компиляция через GitHub Actions](CLOUD_BUILD.md). Нужный Xcode доступен на отдельном runner `xcode-27`; результат успешного задания — iPhone IPA под последующую подпись. Исторические проверки ниже не являются отчётом об этой новой сборке.

## Подготовка

Из корня `telegram_visual_copy`, Python 3 и Git:

```sh
python3 native/scripts/prepare.py
```

Это создаёт `artifacts/native-telegram-ios`. Можно использовать другой **отдельный** checkout той же ревизии:

```sh
python3 native/scripts/prepare.py --checkout /absolute/path/Telegram-iOS
python3 native/scripts/prepare.py --checkout /absolute/path/Telegram-iOS --check
```

Скрипт откажется менять другую ревизию или конфликтующие файлы. Повторный запуск с теми же исходниками допустим. Не используйте каталог настоящего установленного Telegram или его контейнер данных.

Перед Xcode/Bazel потребуется полный checkout и рекурсивные зависимости; загрузка может быть большой:

```sh
python3 native/scripts/prepare.py --full
```

Если использовали `--checkout`, передавайте тот же путь и в следующие команды. На Windows длинные пути Git должны быть разрешены; подготовка нового checkout включает `core.longpaths=true`. Для сборки всё равно нужен macOS.

## Проверки без полноценной iOS-сборки

```sh
swift test --package-path native
python3 native/scripts/test_preparation.py --checkout artifacts/native-telegram-ios
```

Workflow **Native Swift sources** запускает переносимые Swift-тесты в официальном контейнере Swift 6.0 на Linux, синтаксический разбор новых файлов и применение патча к чистым зафиксированным исходникам. Предыдущая версия workflow также прошла на macOS; переносимые проверки отделены от очереди Xcode-runner. Его артефакт `Telegram-Native-Source-Kit` — набор исходников, **не IPA**. Синтаксический разбор не проверяет совместимость UIKit/Telegram API. [Официальные Docker-образы Swift](https://www.swift.org/install/linux/docker/).

## Генерация проекта и сборка на Mac

У upstream собственная система Bazel. Зафиксированный `versions.json` требует **Xcode 27.1, macOS 27, Bazel 9.2.0**. Такое окружение подтверждено полной облачной сборкой на `xcode-27`; версии не понижались. Wrapper проверяет Xcode, остальные проверки выполняет upstream. Инструкция прочитана из самой зафиксированной версии, а не из документации Expo.

Сначала подготовить полный checkout, затем:

```sh
python3 native/scripts/build.py generate-simulator
python3 native/scripts/build.py build-simulator
```

`configuration.simulator.json` содержит **нерабочие API-заглушки и Team ID** для локального режима. Это не учётные данные Telegram. Сеть в нашем форке закрыта на уровне основных запросов, worker-соединений и основной сессии; обходы и отсутствие исходящего трафика ещё нужно проверить на запущенном приложении. Эти заглушки нельзя использовать в сетевом клиенте.

Генератор отключает расширения и provisioning для симулятора. Дополнение `--simulatorLocalMode` к upstream-команде `build` делает то же при полноценной сборке; стандартный upstream флаг генерации сам по себе не переносится на последующий `build`.

Для устройства создайте **неотслеживаемый** `native/configuration.device.json` на основе simulator-конфигурации: собственные уникальные `bundle_id`, `team_id`, URL scheme и выбранная конфигурация API. Настройте свою подпись и provisioning. Пример команд:

```sh
python3 native/scripts/build.py generate-device --configuration native/configuration.device.json
python3 native/scripts/build.py build-device --configuration native/configuration.device.json --signing /absolute/path/codesigning --build-number 1
```

В каталоге подписи ожидаются upstream-структура `profiles/`, `certs/` и соответствующие профили/сертификаты; приватные ключи и конфигурацию в Git не добавлять. Артефакты сборки — `artifacts/native-build`. Для просмотра команды без выполнения есть `--print-command`.

**Sideloadly/SideStore пока не подтверждены для этого форка.** Оригинал использует App Groups, Keychain и другие возможности. Отключение расширений не доказывает совместимость с бесплатной переподписью; нужно проверить запуск с выбранными entitlements на iPhone 13 Pro Max. Подписать ZIP с приложением недостаточно, если его возможности не разрешены профилем.

## Как пользоваться после успешной сборки

1. При запуске открывается оригинальный локальный аккаунт, без входа в настоящий Telegram.
2. Удержание центральной области заголовка около 1,2 секунды открывает редактор. Видимых административных кнопок на публичных экранах нет.
3. Создать виртуальный профиль → личный чат → сообщения. Текст можно писать за обе стороны; менять время, направление, галочки и метку редактирования. Статусы: «в сети», «был(а) недавно», «печатает».
4. Обычное поле ввода отправляет локальное исходящее сообщение. Публичное изменение и удаление перенаправляются в локальный документ.
5. В редакторе можно экспортировать документ или импортировать его после проверки и подтверждения. При импорте исходный файл сохраняется отдельной копией, в том числе если повреждён. Поддерживается документ версии 1 и оболочка резервной копии PWA; web-настройки оформления не переносятся.

Данные хранятся в `Application Support/TelegramSimulator/document-v1.json`. Postbox — проекция для оригинальных экранов; при запуске она восстанавливается из JSON. Основные записи имеют стабильные ID. Даты сообщений ограничены оригинальным 32-битным timestamp (до 2038 года). Одному виртуальному собеседнику соответствует один личный чат.

## Что обязательно проверить на Mac и iPhone

- Полная компиляция TelegramCore/TelegramUI/ChatListUI и зависимостей подтверждена в CI bf3488d. Последующие изменения также должны проходить полную сборку; portable-тесты её не заменяют.
- Первый запуск, отсутствие SMS-входа и исходящих запросов, отсутствие зависшего индикатора загрузки истории, запуск в авиарежиме.
- Оригинальные список, переписку, профиль, настройки, навигацию и клавиатуру. Соответствие сравнивать с Telegram **той же версии**, включая анимации. По правилам upstream нужны запись симулятора и оценка кадров; сейчас их нет.
- Служебный жест, аватар, произвольный телефон, «О себе», обе стороны сообщений, многострочный текст/emoji, произвольные галочки, изменение даты, статус «печатает» и его сброс, непрочитанные.
- Отправку/публичное редактирование/удаление, перезапуск, резервные копии и отказ записи. Неподдерживаемые сетевые действия пока требуют отдельной проверки: они не должны зависать или делать реальные запросы.
- Архив, закрепления, папки и прочие операции оригинала: первоначальная интеграция сохраняет существующее включение чата в Postbox, но полные сценарии ещё не подтверждены. Настройки Postbox не входят в JSON-экспорт переписок.
- Системную подпись, entitlements, совместимость с установленным настоящим Telegram, установку и последующее обновление на телефоне клиента.
